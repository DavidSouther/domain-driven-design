Use subagents to build each skill in the `research/` plugin.

Use general skills, especially general:writing-skills.

**Research skills**

- **Archaeology** answers research questions using the history of the code base. It uses git commands to dig back and attempt to identify why code changed over time.
- **Codebase** answers research questions using the local codebase, at the currently checked out branch. It should prefer issuing queries to an LSP plugin, whenever possible. As a backup, it may use Bash tools to search the code base as well. It should not perform code archaeology, and should not "look back in time" using any git commands. In addition to the SKILL.md itself, prepare reference material for using Rust, Python, and TypeScript LSPs effectively.
- **Dependencies** answers research questions about dependencies of the project. It should only look for dependencies in the project's main configuration (not any lock files). It can use LSP to orient to the dependencies, and if local source dependencies are available it can use Bash to search those. It should make appropriate use of WebSearch and WebFetch tools when the dependency source code isn't available.
- **Domain** answers research questions using the `domain:` skills, if they are loaded.
- **Internal** uses configured MCP servers to search for internal documents to answer research questions.
- **Public** uses WebSearch and WebFetch to find publicly available resources for research questions.

**Jeopardy! Search / Query Expansion** All skills should make use of Jeopardy! search, described in `references/jeopardy.md`, to generate several variants of their queries when searching.

**Research Notes** Before dispatching search subagents, the parent agent should create a folder `docs/research/YYY-MM-DD-<topic>/`, and each subagent skill should write into that folder at `<skill-name>.md` with their findings, including a `**Sources**` section listing what resources were consulted, and citing to those links in the body of the summary
